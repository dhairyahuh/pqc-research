## 2. Summary of Key Audit Discoveries & Contributions

1. **Unmonitored Inverse NTT Operations**:
   Phase 7G claimed "Native ML-KEM NTT Monitor Integration." The audit identified that only forward NTT (5,376 butterflies) is monitored. Inverse NTT (4,480 butterflies) is unmonitored.
2. **Phase 7G Serialization Counter Leak**:
   Discovered that Phase 7G's trial runner logged `cfg2_reused_t.recovered` by reading `g_ntt_native_monitor.recovered_count` after `cfg3_recomputed_t` had executed, and logged `recovered: false` on uncorrupted negative controls. Remediated in Phase 7H with isolated state per configuration.
3. **Dead Trusted Zetas Table**:
   Found that `g_trusted_zetas[128]` declared in `mlkem_fault_hooks.c` is never read by any function in the codebase.
4. **Public API Fail-Stop Defect**:
   Found that `fail = 0xFF` in `kem.c` is gated inside `if (internal_status != NULL)`, meaning callers using the standard 3-argument API `mlkem768_dec(ss, ct, sk)` bypass this specific fail-stop assignment (although FO re-encryption still rejects).
