## 2. Detailed Requirements & Measurable Criteria

### SEC-01: End-to-End Confidentiality
- **Definition:** Plaintext telecommands, mission telemetry, and payload data units must remain unreadable to any unauthorized entity, including intermediate space relay nodes and terrestrial eavesdroppers, across the mission lifetime and post-mission quantum horizon.
- **Enforcement Mechanism:**
  - NIST FIPS 203 ML-KEM-768 key encapsulation producing 256-bit shared secrets.
  - AES-256 in Galois/Counter Mode (GCM, NIST SP 800-38D) with unique 96-bit nonces.
  - Enforced via RFC 9172 Block Confidentiality Blocks (BCB).
- **Measurable Acceptance Criteria:**
  - **Ciphertext Indistinguishability:** Zero leakage of plaintext bytes across intermediate relay node memory. Ciphertext entropy $\ge 7.99$ bits/byte.
  - **Quantum Security Level:** NIST Security Category 3 ($\ge 192$ bits of classical and quantum security).

### SEC-02: Message & Header Integrity
- **Definition:** Any unauthorized alteration, insertion, or deletion of bits in the bundle headers or payload data during transmission or storage must be detected before application delivery.
- **Enforcement Mechanism:**
  - AES-256-GCM 128-bit authentication tag verification over ciphertext and associated data.
  - NIST FIPS 204 ML-DSA-65 digital signatures covering the entire bundle envelope.
- **Measurable Acceptance Criteria:**
  - **Tamper Detection Rate:** **100.0% detection** of single-bit and multi-bit modifications in transit.
  - **False Acceptance Rate (FAR):** $\le 2^{-128}$ (bounded by GCM tag collision and ML-DSA EUF-CMA security).

### SEC-03: Sender Authentication & Non-Repudiation
- **Definition:** The receiving spacecraft or ground station must definitively verify the genuine identity of the originating node, preventing identity spoofing and repudiation of commands.
- **Enforcement Mechanism:**
  - RFC 9172 Block Integrity Block (BIB) containing an ML-DSA-65 digital signature generated by the sender's private signing key.
- **Measurable Acceptance Criteria:**
  - **Forgery Resistance:** Zero successful bundle validations from unauthenticated sources across $10^6$ test vectors.
  - **Standard Conformance:** Verification passes 100% of NIST FIPS 204 KAT vectors (`tests/kat_mldsa65.c`).

### SEC-04: Fine-Grained Authorization
- **Definition:** Only bundles containing valid credentials matching mission security policies may execute critical commands (e.g., orbit changes, payload activation).
- **Enforcement Mechanism:**
  - Cryptographic policy binding embedded in the authenticated associated data (AAD) of the BCB block, linking sender EID, mission role, and permitted command classes.
- **Measurable Acceptance Criteria:**
  - **Unauthorized Execution:** Zero execution of commands outside the sender's authorized policy profile.

### SEC-05: Message Freshness
- **Definition:** Received bundles must have been generated within a valid, mission-defined operational timeframe, preventing the execution of stale commands.
- **Enforcement Mechanism:**
  - BPv7 Creation Timestamp paired with a bounded Time-To-Live (TTL) expiration window calibrated for space delays.
- **Measurable Acceptance Criteria:**
  - **Stale Rejection:** Bundles arriving after `Current_Time > Creation_Time + TTL` are discarded prior to cryptographic processing.

### SEC-06: Strict Replay Protection
- **Definition:** Genuine, previously transmitted and authenticated bundles must not be re-executed if captured and replayed by an adversary.
- **Enforcement Mechanism:**
  - Three-layer defense:
    1. Monotonically increasing bundle sequence number per sender EID.
    2. Fixed-memory sliding-window Bloom filter recording processed bundle IDs.
    3. Monotonic Post-Quantum Double Ratchet sequence indices ($N_{step}$).
- **Measurable Acceptance Criteria:**
  - **Replay Detection Rate:** **100.0% rejection** of duplicated bundles across all transmission channels. Memory footprint remains bounded under 16 KB.

### SEC-07: Communication Availability
- **Definition:** Legitimate communication must not be severed by countermeasure latency, memory exhaustion, or unnecessary system resets.
- **Enforcement Mechanism:**
  - Zero-heap C99 implementation; static buffer bounds.
  - Asynchronous non-blocking store-and-forward bundle spooling.
- **Measurable Acceptance Criteria:**
  - **Decapsulation Overhead:** End-to-end decapsulation latency overhead $\le +20.0\%$ (empirically measured at **+16.90%** on ML-KEM-768).
  - **Memory Stability:** Zero dynamic allocation leaks (`valgrind`/ASan clean).

### SEC-08: Cryptographic Endpoint Fault Resilience
- **Definition:** Computational bit-flips in microprocessor registers or arithmetic units induced by cosmic radiation during cryptographic execution must be detected and resolved without corrupting session keys (SDC) or crashing the flight computer.
- **Enforcement Mechanism:**
  - Sub-word algebraic invariant monitoring on forward Cooley-Tukey and inverse Gentleman-Sande NTT butterflies ($9{,}856$ operations).
  - Register snapshotting (`u_saved, v_saved`) and localized in-place rollback ($R_{max}=2$).
  - Twiddle Factor Integrity Binding (`tfib_ref.c`).
  - Persistent fail-stop escalation to FIPS 203 implicit rejection.
- **Measurable Acceptance Criteria:**
  - **Silent Data Corruption (SDC):** **0 SDC observed** across 750 active fault trials. Formal 95% Clopper-Pearson confidence bound of **$\le 0.49\%$**.
  - **Transient Recovery Rate:** **100.0% recovery** of single-bit register upsets in $\le 2$ retries without call-stack unwinding.
  - **Crash Prevention:** Zero processor exceptions or unhandled traps under persistent stuck-at faults.

### SEC-09: Auditability & Spacecraft FDIR Bridge
- **Definition:** All cryptographic operations, fault detections, localized rollbacks, and fail-stop occurrences must be recorded in deterministic telemetry counters for ground analysis.
- **Enforcement Mechanism:**
  - Dedicated telemetry struct `astra_pqc_telemetry_t` tracking transient recoveries, persistent fail-stops, and twiddle mismatches.
  - Append-only audit logging on ground receiving endpoints.
- **Measurable Acceptance Criteria:**
  - **Telemetry Completeness:** 100% of detected arithmetic faults and fail-stop escalations are reflected in telemetry counters with zero unlogged events.

### SEC-10: Crash & Restart Recovery
- **Definition:** An unexpected node power loss or watchdog reboot must not corrupt the ongoing cryptographic state, leak keys, or induce desynchronization.
- **Enforcement Mechanism:**
  - Atomic non-volatile journaling (NVRAM) of ratchet state variables ($N_{step}$, root key seed) prior to dispatch.
- **Measurable Acceptance Criteria:**
  - **Post-Reboot Resynchronization:** Following simulated node crash, node resumes valid communications without requiring ground-station manual rekeying.
