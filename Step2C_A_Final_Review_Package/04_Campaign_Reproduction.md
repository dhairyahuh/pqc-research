## 4. Confirmation of Genuine Record Generation

All 900 records were actively regenerated by executing the full C harness:
1. `mlkem768_keypair_derand` generated public and secret keys from deterministic PRF seeds.
2. `independent_oracle_encaps_derand` generated ciphertexts and expected shared secrets.

4. Final shared secrets and return statuses were matched against independent oracle references.
5. All 900 CSV rows were written anew by the runner process.

## 5. Critical Epistemological Distinction: Deterministic Reproduction vs Model Validation

It is vital to distinguish between **deterministic computational reproduction** and **independent scientific validation**:

- **What Byte-Identical Reproduction Proves:**
  Because the PRF inputs, key generation seeds, and fault injection offsets are fully specified in `campaign_prf.h` and executed deterministically, running the binary on the same architecture reproduces the exact identical 900 trial outcomes byte-for-byte. This confirms the implementation's determinism, code stability, and internal consistency.
  
- **What Byte-Identical Reproduction Does NOT Prove:**
  Byte-identical reproduction does **not** constitute independent validation of the underlying fault model or physical hardware behavior. It demonstrates that the software simulation is deterministic and follows the implemented logic; it does not validate that the simulation captures physical radiation effects, microarchitectural coupling, or real-world fault dynamics.
