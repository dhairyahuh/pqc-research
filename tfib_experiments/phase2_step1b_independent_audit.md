## 1. Executive Summary & Verdict

### Final Decision: **CONDITIONALLY VERIFIED; SPECIFIC ISSUES MUST BE RESOLVED**

### Summary of Audit Findings
1. **Runner Oracle Integration:** **Verified.** The primary targeted fault-campaign runner (`tfib_experiments/tfib_experiment_runner.c`) was successfully modified to call the independent reference oracle (`independent_oracle_decaps` and `independent_oracle_compute_rejection`). The circular dependency on in-tree `mlkem768_shake256` for expected rejection keys and internal `mlkem768_enc` for valid shared secrets has been eliminated.
2. **Binary Linkage & Isolation:** **Verified.** The built runner binary `tfib_experiments/tfib_experiment_runner` dynamically links `/opt/homebrew/opt/liboqs/lib/liboqs.9.dylib` and imports `_OQS_KEM_ml_kem_768_decaps`. No production twiddle tables or TFIB state are linked into the oracle static archive.
3. **Integration Test Harness (`test_oracle_integration.c`):** **Partially Verified.** The five integration tests (Tests A–E) pass with exit code `0`. However, architectural inspection reveals that Tests A–D do not invoke `run_suite()` in `tfib_experiment_runner.c` directly; instead, they replicate the trial decapsulation calls in separate local test blocks. Test D simulates an oracle error via a local synthetic branch rather than intercepting a live campaign trial.
4. **Ciphertext Generation Provenance:** **Partially Verified.** In `tfib_experiment_runner.c:59`, the runner still invokes in-tree `mlkem768_enc(ct, ss_enc_scratch, pk)` to produce the trial ciphertext `ct`. Although the returned shared secret `ss_enc_scratch` is ignored and `ss_expected` is established independently via `independent_oracle_decaps`, ciphertext generation still depends on the DUT's IND-CPA encapsulation implementation.
5. **Historical Data Preservation:** **Verified.** Pre- and post-test metadata inspections confirm that historical files (`tfib_raw_results.csv`, `tfib_trial_level_results.csv`, and `chatgpt/*`) remain byte-for-byte identical to their pre-audit state.

## 3. Oracle Data-Flow Trace

### 3.1 Trace of Valid Decapsulation Path
```
Line 58: mlkem768_keypair(pk, sk);
Line 59: mlkem768_enc(ct, ss_enc_scratch, pk);
Line 62: int o_rc = independent_oracle_decaps(ss_expected, ct, sk);
         ├── Check: if (o_rc != 0) exit(1);
Line 84: int rc = mlkem768_dec_monitored(ss_out, ct, sk, &status);
Line 91: bool ss_match = (memcmp(ss_out, ss_expected, SS_BYTES) == 0);
```
- **Provenance:** `pk` and `sk` are generated by production keygen; `ct` is generated by production encaps.
- **Oracle Invocation:** `independent_oracle_decaps` takes `(ss_expected, ct, sk)`. It delegates to `OQS_KEM_ml_kem_768_decaps` in external `liboqs.9.dylib`.
- **Expected Secret Derivation:** `ss_expected` is established exclusively by `liboqs`. The production encapsulation output `ss_enc_scratch` is completely discarded.
- **Buffer Ownership:** `ss_expected`, `ss_out`, and `ss_enc_scratch` are distinct 32-byte stack buffers.
- **Finding:** No circular reuse of the production decapsulation result exists.

### 3.2 Trace of Canonical Implicit Rejection Path
```
Line 69: int rej_rc = independent_oracle_compute_rejection(ss_rej_expected, sk, ct);
         ├── Check: if (rej_rc != 0) exit(1);
         └── Extract: z = sk + (2400 - 32) = sk + 2368
         └── Permute: fips202_ref_shake256(ss_rej_expected, 32, z || ct, 32 + 1088)
Line 84: int rc = mlkem768_dec_monitored(ss_out, ct, sk, &status);
Line 92: bool rej_match = (memcmp(ss_out, ss_rej_expected, SS_BYTES) == 0);
```
- **Ciphertext Exactness:** The pointer `ct` passed to `independent_oracle_compute_rejection` is the identical buffer passed to `mlkem768_dec_monitored`.
- **Rejection Component:** `z = sk[2368..2399]` adheres strictly to FIPS 203 Section 6.1 and Algorithm 17.
- **Engine Isolation:** Computed using standalone TweetFIPS-202 `fips202_ref_shake256`; in-tree `mlkem768_shake256` is not invoked.
- **Finding:** Canonical rejection derivation is independent and mathematically conformant.

## 6. Error Handling & Binary Inspection

### 6.1 Runner Error Handling Audit
- In `tfib_experiment_runner.c:63–73`:
  ```c
  int o_rc = independent_oracle_decaps(ss_expected, ct, sk);
  if (o_rc != 0) {
      fprintf(stderr, "FATAL: independent_oracle_decaps failed on authentic input (trial %d)!\n", t);
      exit(1);
  }
  int rej_rc = independent_oracle_compute_rejection(ss_rej_expected, sk, ct);
  if (rej_rc != 0) {
      fprintf(stderr, "FATAL: independent_oracle_compute_rejection failed (trial %d)!\n", t);
      exit(1);
  }
  ```
- **Auditor Assessment:** Both oracle return codes are checked with explicit fatal exits. An oracle failure terminates the runner with exit code `1`, preventing any unvalidated trial from being written to the CSV.
- **Production Decapsulation Return Code:** Line 84: `int rc = mlkem768_dec_monitored(ss_out, ct, sk, &status); (void)rc;`. As noted in Phase 1B, ML-KEM decapsulation is designed to be constant-time and never returns an error code; diagnostic status is passed via `uint32_t status`. This is standard FIPS 203 behavior.

## 7. Defects, Uncertainties, and Evidence Gaps

### Defect 1: Ciphertext Generation Residual Coupling (Severity: Low)
- **Source:** `tfib_experiments/tfib_experiment_runner.c:59`
- **Description:** `mlkem768_enc(ct, ss_enc_scratch, pk)` is still called to generate the trial ciphertext `ct`. While `ss_enc_scratch` is ignored and `ss_expected` is established via `independent_oracle_decaps`, the campaign still relies on the DUT's encapsulation routine to construct the ciphertext.
- **Recommended Remediation in Step 2:** Use `independent_oracle_encaps_derand` to generate both `ct` and `ss_expected` from uniform random seed $m$, eliminating production encapsulation from the trial input generation path entirely.

### Defect 2: Integration Tests Do Not Call `run_suite` Directly (Severity: Medium)
- **Source:** `tfib_experiments/test_oracle_integration.c`
- **Description:** Tests A, B, C, D, and E duplicate the trial logic in local blocks rather than calling `run_suite()` from `tfib_experiment_runner.c`. Because `run_suite` is defined as `static` inside `tfib_experiment_runner.c`, it was not linked as an exported function.
- **Auditor Assessment:** While the mathematical calls are identical, this means the integration test binary is a parallel implementation rather than an execution wrapper around `tfib_experiment_runner.c`.

### Defect 3: Synthetic Error Handling in Test D (Severity: Low)
- **Source:** `tfib_experiments/test_oracle_integration.c:178–182`
- **Description:** Test D demonstrates that the oracle API rejects NULL pointers, but validates error handling through a local conditional variable rather than executing an end-to-end trial failure test.

### Rationale
1. **Core Objective Met:** The circular oracle ground-truth vulnerability has been eliminated in `tfib_experiments/tfib_experiment_runner.c`. Both valid decapsulation and canonical implicit rejection now evaluate against external reference implementations (`liboqs 0.16.0` and TweetFIPS-202).
2. **Historical Data Fully Protected:** Historical campaign results (`tfib_raw_results.csv`, `tfib_trial_level_results.csv`, `chatgpt/*`) are untouched.

   - Replace standard `rand()` with CSPRNG (`arc4random_buf`).
   - Remove internal test-harness coupling flags (`locus` in `tfib_meta.c` and `!persistent` in `tfib_ref.c`).
   - Relocate colocated twiddle factor tables.
