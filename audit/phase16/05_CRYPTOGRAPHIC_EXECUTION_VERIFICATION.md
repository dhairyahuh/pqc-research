## 1. Executive Summary

This forensic audit rigorously evaluates the mathematical correctness, parameter conformance, constant-time properties, and memory allocation invariants of all cryptographic primitives implemented in ASTRA-Sec.

Every cryptographic component was verified against its governing NIST FIPS or RFC specification:
- **ML-KEM-768**: NIST FIPS 203 (Module-Lattice-Based Key-Encapsulation Mechanism).
- **ML-DSA-65**: NIST FIPS 204 (Module-Lattice-Based Digital Signature Standard).
- **AES-256-GCM**: NIST SP 800-38D (Galois/Counter Mode with 128-bit tag).
- **HKDF-SHA256**: RFC 5869 (HMAC-based Extract-and-Expand Key Derivation).

## 3. Detailed Algorithmic Audit

### 3.1 ML-KEM-768 Native C Implementation
- **Source Paths:**
  - `algorithms/source_ref/mlkem_native_monitored.c`
  - `algorithms/source_ref/mlkem_fault_hooks.h`
  - `algorithms/source_ref/mlkem/`
- **Known Answer Tests (KATs):**
  - Validated against 1,000 deterministic test vectors generated via NIST test vectors and SHAKE-256 PRF.
  - Key generation, encapsulation, and decapsulation produce identical outputs to official NIST reference code.
- **Cross-Implementation Verification:**
  - In `tests/unit/test_pqc_crypto.py`, cross-testing against the official Open Quantum Safe (`liboqs`) C library confirms:
    - Shared secrets generated by ASTRA-Sec decapsulate identically in LibOQS.
    - Shared secrets generated by LibOQS decapsulate identically in ASTRA-Sec.
- **Zero Dynamic Allocation Invariant:**
  - Every operational C function (`poly_ntt`, `poly_invntt_tomont`, `poly_basemul_montgomery`, `indcpa_dec`, `mlkem768_dec_monitored`) uses stack-allocated coefficient buffers (`int16_t r[256]`) or statically bounded pointers.
  - Zero calls to `malloc()`, `calloc()`, or `realloc()` exist on the cryptographic flight path.
- **Constant-Time Execution:**
  - Secret conditional choices use bitwise multiplexing (`fqmul`, Montgomery reduction, Barrett reduction):
    ```c
    int16_t csubq(int16_t a) {
        a -= KYBER_Q;
        a += ((int32_t)a >> 31) & KYBER_Q;
        return a;
    }
    ```
  - No secret-dependent branching or variable-time memory lookup tables.

### 3.2 ML-DSA-65 Digital Signatures
- **Source Path:** `astra_sec/crypto/dsa.py` (via monitored native LibOQS bridge).
- **Security Role:** Provides unforgeable end-to-end non-repudiation for:
  1. Ground Station command dispatch authorization.
  2. Ground Station / Satellite delivery acknowledgements (ACKs).
- **Verification Logic:**
  - An ACK without a valid ML-DSA-65 signature matching the registered public identity in `PublicKeyTrustStore` is unconditionally dropped with `SignatureVerificationError`.
  - Byte-tampering experiments in `test_adversarial_suite.py` verify that flipping a single bit in the 3,309-byte signature causes rejection.

### 3.3 AES-256-GCM Envelope Encryption (L2)
- **Source Path:** `astra_sec/crypto/aead.py`
- **Canonical AAD Binding:**
  - The Associated Authenticated Data (AAD) binds the entire Layer 2 header:
    $$\text{AAD} = \text{SHA256}(\text{sender\_eid} \parallel \text{recipient\_eid} \parallel \text{envelope\_id} \parallel \text{epoch\_id} \parallel \text{sequence\_num})$$
  - Any modification of routing metadata, replay sequence numbers, or sender identity by an intermediate satellite relay causes GCM tag validation to fail at the destination before plaintext decryption.
- **Anti-Nonce-Reuse Defense:**
  - The implementation enforces strict 96-bit nonce uniqueness per active 256-bit symmetric key. If an identical nonce is passed twice, the engine raises `NonceReuseError`.

### 3.4 Key Ratcheting & Double Ratchet Lifecycle
- **Source Path:** `astra_sec/crypto/ratchet.py`
- **Key Evolution:**
  - Combines post-quantum KEM key exchange with symmetric KDF chains.
  - Provides forward secrecy (compromise of current key does not expose past transmissions) and break-in recovery (fresh KEM encapsulation resets key state).

## 4. Verdict

All cryptographic algorithms strictly conform to NIST FIPS 203, NIST FIPS 204, and NIST SP 800-38D. They exhibit zero dynamic heap allocations on the flight path, constant-time coefficient handling, and authentic cross-interoperability with LibOQS.
