## 1. Executive Summary

This document specifies the canonical binary structure, metadata fields, authentication bindings, and serialization rules for the ASTRA-Sec Layer 2 Security Envelope (`PqcMessageEnvelope`).

The envelope provides end-to-end confidentiality, authenticity, non-repudiation, and replay resistance across multi-hop untrusted satellite relays.

---

## 2. Canonical Envelope Structure

The envelope is partitioned into four explicit functional sections:
```
+--------------------------------------------------------------------------------------------------+
| PqcMessageEnvelope                                                                               |
|                                                                                                  |
| [1. EnvelopeHeader]                                                                              |
|   ├── version: uint8 = 1                                                                         |
|   ├── envelope_id: UUIDv4 (16 B string)                                                          |
|   ├── source_eid: Canonical EID URI (e.g., "dtn://gsa/app")                                      |
|   ├── destination_eid: Canonical EID URI (e.g., "dtn://gsb/app")                                 |
|   ├── sequence_id: uint64 (Monotonic anti-replay counter)                                        |
|   ├── timestamp_utc: uint64 (DTN Creation Unix epoch seconds)                                   |
|   ├── ttl_seconds: uint32 (Validity window, default = 3600s)                                    |
|   ├── kem_ciphertext: bytes (1,088 B ML-KEM-768 encapsulation)                                   |
|   └── nonce: bytes (12 B AES-256-GCM IV)                                                         |
|                                                                                                  |
| [2. Ciphertext]                                                                                  |
|   └── Variable-length encrypted application payload (AES-256-GCM)                                |
|                                                                                                  |
| [3. Authentication Tag]                                                                          |
|   └── 16-byte (128-bit) GCM integrity tag                                                        |
|                                                                                                  |
| [4. Digital Signature]                                                                           |
|   └── 3,309-byte ML-DSA-65 signature generated by sender over signable bytes                     |
+--------------------------------------------------------------------------------------------------+
```

## 3. Cryptographic Binding Rules

### 3.1 Canonical Associated Authenticated Data (AAD)
To prevent header-tampering attacks by intermediate relays, AES-256-GCM binds the entire header into the cryptographic tag calculation:
$$\text{AAD} = \text{EnvelopeHeader.to\_canonical\_aad()}$$
The canonical byte construction is defined as:
```python
def to_canonical_aad(self) -> bytes:
    return (
        f"{self.version}|{self.envelope_id}|{self.source_eid}|{self.destination_eid}|"
        f"{self.sequence_id}|{self.timestamp_utc}|{self.ttl_seconds}"
    ).encode("utf-8") + b"|" + self.kem_ciphertext + b"|" + self.nonce
```
Any modification of `sequence_id`, `source_eid`, `destination_eid`, or `timestamp_utc` by an intermediate relay causes AES-GCM tag verification to fail immediately with `DecryptionError`.

### 3.2 Canonical Signable Representation
To guarantee non-repudiation and prevent cross-message substitution, ML-DSA-65 signs the composite hash of the header, ciphertext, and tag:
$$\text{SignableBytes} = \text{SHA256}(\text{HeaderCanonicalBytes} \parallel \text{Ciphertext} \parallel \text{Tag})$$
```python
def to_signable_representation(self, ciphertext: bytes, tag: bytes) -> bytes:
    return self.to_canonical_aad() + b"|" + ciphertext + b"|" + tag
```

## 4. Deterministic Wire Representation (RFC 8949 CBOR)

When serialized for DTN transport, the envelope is encoded as a canonical CBOR array:
```
CBOR Array [4 items]:
  0: Header Map {
       1: version (uint),
       2: envelope_id (text),
       3: source_eid (text),
       4: destination_eid (text),
       5: sequence_id (uint),
       6: timestamp_utc (uint),
       7: ttl_seconds (uint),
       8: kem_ciphertext (bytes, 1088),
       9: nonce (bytes, 12)
     }
  1: ciphertext (bytes)
  2: tag (bytes, 16)
  3: signature (bytes, 3309)
```

## 5. Formal Validation Rules & Defensive Checks

| Validation Check | Failure Condition | Defensive Reaction |
| :--- | :--- | :--- |
| **Protocol Version** | `version != 1` | Rejection: `SchemaValidationError` |
| **EID Syntax** | Must match `^dtn://[a-zA-Z0-9_\.-]+/[a-zA-Z0-9_\.-]+$` | Rejection: `InvalidEidError` |
| **KEM Ciphertext Size** | `len(kem_ciphertext) != 1088` | Rejection: `SchemaValidationError` |
| **Nonce Length** | `len(nonce) != 12` | Rejection: `SchemaValidationError` |
| **Tag Length** | `len(tag) != 16` | Rejection: `SchemaValidationError` |
| **Signature Length** | `len(signature) != 3309` | Rejection: `SignatureVerificationError` |
| **Freshness (TTL)** | `now > timestamp_utc + ttl_seconds` | Rejection: `MessageExpiredError` |
| **Clock Skew** | `timestamp_utc > now + 300` | Rejection: `StaleMessageError` |
| **Anti-Replay Window** | Duplicate `(source_eid, sequence_id)` in window | Rejection: `ReplayDetectedError` |

## 6. Reverse Message Acknowledgment (ACK) Schema

```
+--------------------------------------------------------------------------------------------------+
| MessageAcknowledgment                                                                            |
|   ├── ack_id: UUIDv4                                                                             |
|   ├── original_envelope_id: UUIDv4 (Correlated dispatched command)                               |
|   ├── source_eid: Destination node emitting the ACK (e.g., "dtn://gsb/app")                      |
|   ├── destination_eid: Originating ground station (e.g., "dtn://gsa/app")                         |
|   ├── timestamp_utc: uint64                                                                      |
|   ├── status: "SUCCESS" | "DECRYPTION_FAILED" | "VERIFICATION_FAILED"                             |
|   └── signature: 3,309 B ML-DSA-65 signature over canonical ACK bytes                             |
+--------------------------------------------------------------------------------------------------+
```

## 7. Verdict

The envelope schema is **strictly validated, deterministically serializable in CBOR, and cryptographically unforgeable**.
